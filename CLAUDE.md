# screenwriter_client

Frontend network client library for ViaInk (`screenwriter_api`). Slice F1 of `../screenwriter_plans/plans/2026-09-20-frontend-mvp.md`. Local package: no publishing, no versions, no CI workflow. Consumers import it by path (`tsconfig` `paths` + Vite alias to `../screenwriter_client/src/index.ts`).

## Tech stack

Bun, TypeScript (ESM, `moduleResolution: bundler`), Yjs (V2 encoding), `@tanstack/react-query` v5 and `react` as peer deps, Vitest. Platform-free: global `fetch` and `WebSocket` only, no Node built-ins in `src/` (tests use `node:child_process`).

## Structure

```
src/
  index.ts            barrel
  errors/             ApiError (code, status, details), RoleInsufficientError, ShareLinkExpiredError, isApiError
  network/            NetworkClient interface + createFetchNetworkClient (the only fetch call), retry.ts (policy, gzip, idempotency keys);
                      ScreenwriterClient (typed method per route) + API_ROUTE_METHODS (route -> method map)
  hooks/              query-keys.ts (central factory), query-config.ts, client-context.ts (Provider + useScreenwriterClient),
                      one hook file per resource group (account, user-data, projects, documents, scenes, templates, trash, project-bin, workspace-settings, versions, snapshots, import-export, ai, api-keys, sharing, jobs, reads, search, reports, packets, assets)
  sync/               SyncClient (framework-free), awareness.ts (JSON relay format + RemoteAwareness), backoff.ts
tests/                contract, backoff/awareness units, hooks (fake network), integration (spawns the real API)
```

## Commands

- `bun install`
- `bun run typecheck` (`bunx tsc --noEmit`)
- `bunx vitest run` (never `bun test`). `tests/integration.test.ts` and `tests/sharing-integration.test.ts` spawn `bun run src/index.ts` in `../screenwriter_api` on a random port with `AI_TEST_MODE=1` and `DATABASE_URL=postgres://localhost:5432/screenwriter_test`. ## Patterns

- **DI**: `ScreenwriterClient({network, baseUrl, getToken})`. `baseUrl` is the origin (no `/api/v1`). `getToken(forceRefresh)` is retried once with `true` after a 401. Envelope `data` is unwrapped; failures throw `ApiError` (`code` is an API error code or `NETWORK_ERROR`/`BAD_RESPONSE`).
- **Route contract**: `API_ROUTE_METHODS` is a `Record<ApiRouteName, method | null>`; a new route in `screenwriter_types` fails typecheck until mapped, and `tests/contract.test.ts` allows `null` only for `jobWebhook` (a server-to-server, HMAC route no client calls): full parity otherwise, every route the API declares has a client method. Add the method, its hook and its query key in the same change as the route.
- **Hooks** read the client from `<ScreenwriterClientProvider client>` (inside a `QueryClientProvider`). Keys come from `queryKeys`; mutations invalidate the affected lists/details (create project -> project lists; restore version / open snapshot -> whole document family).
- **Import/export**: `importDocument(pid, {filename, bytes|contentB64, ...})` base64s with `util/base64.ts` (btoa/atob, no `Buffer`); `exportDocument(did, format)` returns decoded `{filename, mimeType, bytes, report, format}`; `getFormats()`. Hooks `useFormats`, `useImportDocument(pid)` (invalidates document lists), `useExportDocument(did)`.
- **Binary state**: `getDocumentState`/`getSnapshotState`/`getVersionState` return `{state: Uint8Array (Yjs V2), epoch, stateVector}`.
- **SyncClient**: see the class doc. Events via `on(event, fn)`: `status`, `docStatus`, `epochChanged`, `authError`, `subscribeError`, `rejected`, `roleChanged`, `documentDeleted`, `stopped`, `closed`, `error`. Per-document handle: `status` (`syncing|synced`), `state` (`pending|active|stale|failed`), `unackedCount`, `setLocalAwareness`, `unsubscribe`.
  - Yjs frames are V2. Remote updates are applied with an internal origin; only non-remote-origin doc updates are sent.
  - Awareness payload is UTF-8 JSON `{clientId: doc.clientID, state}` (server relays opaque bytes). Remote peers expire after `awarenessTimeoutMs` (30 s); local state is re-broadcast at half that.
  - **Epoch changes are reported, not handled.** `epochChanged`, `subscribeError EPOCH_MISMATCH`, `reject EPOCH_MISMATCH` and close 4409 mark the document `stale`, emit `epochChanged({documentId, liveEpoch})` once (`liveEpoch` null if only 4409 was seen) and skip it on reconnect. The caller resumes by calling `subscribe` again with a new doc and epoch (rebase = screenwriter_lib).
  - Close codes: 4401 refresh token once then stop, 4403/4406 stop (`stopped` event), 4400 x3 in 10 min stop, 4429 backs off at least 5 s, 1001 honours `serverShutdown.reconnectAfterMs`, everything else full-jitter exponential backoff (attempt resets after a 60 s healthy connection). `online` event triggers an immediate reconnect.
  - The subprotocol is deliberately NOT offered: the API does not echo `fadewright-sync.v1`, and browsers fail a socket whose offered protocol is not selected.

## Tenancy, roles, sharing (B8)

- **Methods** (one per route, plus dispatchers): `createWorkspace|updateWorkspace|deleteWorkspace(wid, confirmName)|transferWorkspace|leaveWorkspace|getWorkspaceUsage|downloadWorkspaceAudit` (CSV text), `listMembers|updateMemberRole|removeMember`, `inviteToWorkspace|inviteToProject|inviteToDocument` (dispatcher `inviteMember(target, body)`), `listWorkspaceInvitations|listMyInvitations|renewInvitation|cancelInvitation|acceptInvitation(token)|declineInvitation`, `listSharedWithMe`, `lockDocument|unlockDocument|createUnlockSession`, `listDocumentGrants|listProjectGrants` (`listGrants(target)`), `updateGrant|removeGrant`, `createDocumentShareLink|createProjectShareLink|createSnapshotShareLink` (`createShareLink(target, body)`), `listDocumentShareLinks|listProjectShareLinks` (`listShareLinks(target)`), `updateShareLink|revokeShareLink`, public `resolveShareLink(token)` (sent with NO Authorization), `unlockShareLink(token, password?)` (sends the user's token if signed in: a comment session needs it), `getSharedState(token, {linkSession?, documentId?})`. The dispatchers are extras: `API_ROUTE_METHODS` maps each route to its own method (the contract test wants unique methods).
- **Credentials**: `send(..., auth)` with `AuthMode` `"user"` (default, retried once on 401), `"none"`, `{bearer}` (a `linkSession`, never retried with a user token). Public share methods use `none`/`bearer` so they work signed out.
- **Typed errors** (`apiErrorFrom` in `errors/`): `RoleInsufficientError` (403 `FORBIDDEN` whose `details.requiredRole` is set; `.requiredRole`, `.role`, `.permission`) and `ShareLinkExpiredError` (404 `SHARE_LINK_INVALID`; `.reason` `unknown|revoked|expired|unavailable|session`); both extend `ApiError`. A 403 without `requiredRole` (e.g. "you need access" on a restricted link, a read-only key) stays a plain `ApiError`.
- **Unlock sessions**: `createUnlockSession(did)` stores the token; every request to `/documents/<did>/...` then sends `X-Doc-Unlock`. `setDocumentUnlock|getDocumentUnlock` manage it by hand; for the socket pass `getUnlockToken` to `SyncClient` (one token per connection).
- **Hooks** (`hooks/use-sharing.ts`; keys under `queryKeys.sharing()` so one invalidation refreshes a Share dialog; public link reads under `queryKeys.shareLink(token)`): `useMembers`, `useWorkspaceInvitations`, `useMyInvitations`, `useSharedWithMe`, `useGrants(target)`, `useShareLinks(target)`, `useShareLink(token)` (no auth header, no retry on 4xx), `useSharedState`, `useWorkspaceUsage`, and mutations for everything above (`useUpdateMemberRole`, `useRemoveMember`, `useInviteMember({target, body})`, `useAcceptInvitation`, `useCreateShareLink({target, body})` (one-time token: `reset()` after copying), `useUpdateShareLink`, `useRevokeShareLink`, `useShareUnlock(token)`, `useCreateUnlockSession(did)`, ...). Role, membership and accept mutations also invalidate workspaces, projects and documents.
- **Sync**: `SyncClient` `scheme: "link"` (`getToken` returns a `linkSession`, re-sent every 10 min; a revoked link gives `authError LINK_EXPIRED` then close 4401) and `roleChanged` now really arrives (`{documentId, role, markPermissions}`; `role: "none"` is followed by close 4403 = `stopped`). A viewer subscribed in `edit` mode simply has its updates rejected (`rejected` event, code `FORBIDDEN`): read `role` from `roleChanged`/REST and disable editing.
- Tests: `tests/sharing.test.tsx` (fake network), `tests/sharing-integration.test.ts` (real API; reads invitation tokens from the API's dev outbox `INVITATION_OUTBOX_FILE`, cleans up through the API's `postgres`).

## Request funnel, jobs (B9)

- **Funnel** (`ScreenwriterClient.send`, `network/retry.ts`): builds headers (token, `X-Client` from `ClientOptions.clientTag`, `X-Doc-Unlock`, **`Idempotency-Key` on every POST** except `/export`, `/documents/import`, `/(elements|scenes)/batch` and share unlock; one UUID per logical call via `newIdempotencyKey`, reused by every retry), **gzips JSON bodies >= 1 KiB** when `CompressionStream` exists (`Content-Encoding: gzip`; `gzip: false` turns it off; `NetworkRequest.body` is `string | Uint8Array`, `readRequestBody(req)` decodes it in fakes), refreshes the token once on 401 (not a retry attempt), then applies the **retry policy** of spec 10 §2.4 (`ClientOptions.retry`: `false` or a partial `RetryPolicy`): 3 attempts, base 400 ms, cap 8 s, full jitter, `Retry-After` overrides on 429/503 (cap 60 s); retried = no response, 408, 429 `RATE_LIMITED`, 502, 503 (except the "not configured" codes `CONFIG_MISSING`, `AI_UNAVAILABLE`, `STORAGE_UNAVAILABLE`, `GRAMMAR_UNAVAILABLE`, `OCR_UNAVAILABLE`), 504; GET/PUT/DELETE always, POST only with a key, PATCH never; 4xx, `QUOTA_EXCEEDED` never. Tests inject `retry: {sleep, random}` and `newIdempotencyKey`. React Query's own retry stays off in the app's hooks; retry lives here.
- **Errors**: `RateLimitedError` (`retryAfterS`, `bucket`; `Retry-After` is copied into `details.retryAfterS`), `PayloadTooLargeError` (413 `PAYLOAD_TOO_LARGE|IMPORT_TOO_LARGE|ASSET_TOO_LARGE`), `JobKindDisabledError` (501, `.kind`), plus `isRateLimited|isPayloadTooLarge|isJobKindDisabled`.
- **Jobs**: `listJobs({documentId?, kind?, status?, cursor?, limit?})`, `getJob(id, {wait?})` (long-poll, seconds <= 120), `createJob({kind, input, sources, idempotencyKey?, dryRun?})` (202; sends the key as header AND body field so the replay works past the 24 h header window; `dryRun: true` returns `{estimate}`), `cancelJob`, `getJobOutputs` (`data:` URL for inline outputs, signed URL later), `listJobRecipients`. AI jobs stay on `startAiJob`/`getAiJob`; the same job is also readable through `getJob` (D21a). Hooks in `hooks/use-jobs.ts`, keys under `queryKeys.jobs()`: `useJobs(query)`, `useJob(id)` (polls 1 s for the first 30 reads, then 5 s, stops when terminal: `jobPollInterval`), `useJobOutputs(id, enabled)`, `useJobRecipients`, `useCreateJob`, `useCancelJob`.
- Tests: `tests/jobs.test.tsx` (fake network: funnel, retry, hooks), `tests/jobs-integration.test.ts` (spawns two real APIs: lost-response retry creates one job, gzip, typed errors, rate limit with `Retry-After`, AI mirror).

## Account and per-user data (B13)

- **Methods**: `getPreferences`, `setPreferences(update, base?)`, `getDictionary`, `updateDictionary({add, remove})`, `listMacros|createMacro|updateMacro|deleteMacro`, `getWritingStats(query)`, `recordWritingSession(body)` (`newWritingSessionId()` makes the `clientSessionId`), `getWritingGoals|setWritingGoals(goals[])`, `requestAccountExport` (a `Job`: `useJob` then `getJobOutputs`, a `data:` zip URL), `deleteAccount` (sends `{confirm: "DELETE"}`), `restoreAccount`, `getMyDocumentState(did)|setMyDocumentState(did, update, base?)`, `starDocument|unstarDocument`.

## Assets and R2 (B11)

- **Methods** (one per route): `initAssetUpload(wid, body)`, `getAssetUpload(uploadId)` (resume: `completedParts`), `signAssetUploadParts(uploadId, partNumbers)`, `completeAssetUpload(uploadId, body)` (idempotent), `abortAssetUpload(uploadId)`, `listAssets(query)`, `getAsset(aid)`, `getAssetUrl(aid, vid, query?)`, `updateAsset(aid, body)`, `deleteAsset(aid)`, `restoreAsset(aid)`, `createAssetLink(body)`, `listDocumentAssetLinks(did, query?)`, `updateAssetLink(lid, body)`, `unlinkAsset(lid)`, `getDocumentStaleness(did, query?)`, `getAssetLinkStaleness(lid)`.
- **`uploadAsset(wid, file, opts)`**: the whole multipart plan in one call. `file: UploadableFile = File | Blob | {uri, name, type}` (the last form is read through platform `fetch`, for React Native and similar). `opts.kind` is required; `title`, `assetId` (client-minted, offline), `parentVersionId` (new version of an existing asset), `provenance`, `rights`, `onProgress(fraction)`, `concurrency` (default `ASSET_UPLOAD_CONCURRENCY`, 3), `partRetries` (default 3), `signal`. Whole-file `sha256Hex` is computed up front only below `PREHASH_MAX_BYTES` (64 MiB) — enables server-side dedup before any bytes are sent; a bigger file skips it and leans on the server's own streaming re-hash at `complete`. A part failing all its retries throws `AssetUploadInterruptedError(message, uploadId, cause)`: persist `uploadId` and resume with `uploadAsset(wid, file, {...opts, resumeUploadId: uploadId})` (re-lists what the storage already has via `getAssetUpload`, re-signs and sends only the missing parts). A deduplicated init (`AssetUploadInit.deduplicated`) skips every PUT and completes immediately.
- **Hooks** (`use-assets.ts`, keys `queryKeys.assetLists`/`asset`/`assetUpload`/`assetUrl`/`assetLinkStaleness`, and `documentAssetLinks`/`documentStaleness` under `documentFamily(did)` — a scene/entity edit can make these stale, so `useApplyCommands` refreshes them too): `useAssets(query)`, `useAsset(aid)`, `useAssetUrl(aid, vid, query?)`, `useUpdateAsset`, `useDeleteAsset`, `useRestoreAsset`, `useAssetLinks(did, query?)`, `useCreateAssetLink`, `useUpdateAssetLink`, `useUnlinkAsset`, `useStaleness(did, query?)`, `useAssetLinkStaleness(lid)`, the four low-level upload mutations (`useInitAssetUpload`, `useSignAssetUploadParts`, `useCompleteAssetUpload`, `useAbortAssetUpload`, `useAssetUpload(uploadId)` for polling a resume), and `useUploadAsset()` (the composite: `mutateAsync({wid, file, opts})`, plus a live `progress` field on the hook's return value that updates on every part, separate from react-query's own `data`/`status`).

## Versions, snapshots and sync completion (B15)

- **Methods** (one per route): `restoreVersionAsCopy(did, vid, {title, targetProjectId?})` (a new `DocumentMeta`; the source is untouched, nothing to rebase), `getElementHistory(did, elementId, {limit, cursor})` (newest first: `source: "update"` author sessions from the raw log, then `"version"` points), `getPresence(did)` (one entry per device on the API instance), `compare(did, {base, target, granularity?, ignoreFormatting?, ignoreRevisionMarks?, ignoreTrackedChanges?})` (`SourceRef`s: `{kind: "live", documentId}`, `{kind: "snapshot", snapshotId}`, `{kind: "version", documentId, versionId}`; no `Idempotency-Key`, it is a read), `setSnapshotPrefs(sid, hidden)`, `listSnapshotNotes|addSnapshotNote(sid, body)` (append-only, cap 200), `listSnapshotComments|addSnapshotComment|copyCommentToLive|resolveSnapshotComment`. `createSnapshotFromState(did, state, body)` = `uploadStateBytes` + `createSnapshot` with `state: {uploadKey}`: the offline-edits flow of spec 03 §6.3 (`kind: "auto"`, `autoReason: "offline-edits"`, `clientSnapshotId: "offline-edits:<deviceId>:<oldEpoch>"`, `sourceEpoch: <old epoch>`, `assumedParentId`, `createdAt`, `createdOnDevice`); a snapshot at an old epoch never re-parents or merges into the live document, and a replay with the same `clientSnapshotId` returns the same snapshot. `SnapshotSummary` now carries real `hiddenForMe`, `noteCount`, `createdOnDevice`, `receivedAt`.

## Collaboration, notifications, devices, email (B12)

- **Methods** (one per route): `getNotificationPrefs`, `setNotificationPrefs(update)` (a sparse per-kind patch, e.g. `{kinds: {mention: {email: "off"}}}`; never a whole-document replace), `listNotifications(query)` (`{items, nextCursor, unreadCount}` — reads `X-Unread-Count`, not a second call), `markNotificationsRead({ids?, all?, before?})`, `deleteNotification(nid)`, `openNotificationStream(onEvent, opts?)`, `listMentionsWithoutAccess(did)`, `listChat(did, query?)`, `sendChatMessage(did, {clientMessageId?, body, mentions?})` (`clientMessageId` defaults to a fresh `newChatMessageId()`, so a retried send is idempotent), `editChatMessage(mid, {body})`, `deleteChatMessage(mid)`, `listDocumentActivity(did, {kinds?, cursor?})` (`kinds` joins as `a,b`, like search's `types`), `listWorkspaceActivity(wid, {projectId?})`, `listDevices(currentDeviceId?)` (marks that one `current: true`; not a spec query param, harmless), `registerDevice(body)`, `updateDevice(devid, {displayName})`, `revokeDevice(devid)`, `setPushToken(devid, body)`, `clearPushToken(devid)`.
- **`openNotificationStream`** is the one method that bypasses `NetworkClient` on purpose (like `SyncClient` bypasses it for `WebSocket`): `EventSource` cannot send an `Authorization` header, so it calls the platform `fetch` directly with a bearer token, reads `res.body.getReader()` and parses raw `event:`/`data:` SSE frames (events `notification`, `unread_count`, a `heartbeat` every 25 s). On any drop (network error, non-OK response, or the stream just ending) it reconnects with `sync/backoff.ts`'s full-jitter policy (`opts.random` is a test seam); `opts.onStatus` reports `connecting|open|closed`; `handle.close()` stops it for good, no further reconnects.
- **Hooks** (`use-notifications.ts`, `use-chat.ts`, `use-activity.ts`, `use-devices.ts`): `useNotificationPrefs`, `useSetNotificationPrefs`, `useNotifications(query?)`, `useUnreadCount()` (a minimal `listNotifications({limit: 1, unread: true})` just to read the header, so the badge does not fetch full pages), `useMarkNotificationsRead`, `useDeleteNotification`, `useMentionsWithoutAccess(did)`, `useNotificationStream(opts?)` (opens the stream for the component's lifetime and invalidates the notification queries on every event — mount it once, e.g. near the app root), `useChat(did, query?)`, `useSendChatMessage(did)`, `useEditChatMessage(did)`, `useDeleteChatMessage(did)`, `useActivity(did, query?)`, `useWorkspaceActivity(wid, query?)`, `useDevices(currentDeviceId?)`, `useRegisterDevice`, `useUpdateDevice`, `useRevokeDevice`, `useSetPushToken`, `useClearPushToken`.
- **Keys**: `notificationPrefs()`, `notifications()` family (`notificationList(filters)`, `unreadCount()`), `devices()` (not per-document); `mentionsWithoutAccess(did)` and `chat(did, filters)` and `documentActivity(did, filters)` sit under `documentFamily(did)` for convenience (chat/activity are not document content, but grouping them lets a document-family invalidation refresh them too); `workspaceActivity(wid, filters)` is its own family.
- **F-NOTE-005** (a location link posted in chat resolves for another collaborator): the chat DTO has no locator field — a poster just types a reference (a raw id, `#12A`, etc.) into `body`; the app is expected to detect it and call B10's `resolveLocators`/`resolveLocator` to turn it into a link. There is nothing chat-specific to call here beyond `sendChatMessage`/`listChat`.
- **No new typed error subclasses**: `FORBIDDEN` (chat edit by a non-author, mentions-without-access without `share.manage`), `EDIT_WINDOW_CLOSED` (a chat edit past 15 minutes), `DEVICE_REVOKED` (setting a push token on a revoked device), `ID_CONFLICT` (a chat/device id reused by another author or account) all stay a plain `ApiError` (check `.code`) — none carries extra `details` worth a dedicated class, matching how B14 left `FOLDER_DEPTH`/`MOVE_FORBIDDEN`/etc. plain.
- Tests: `tests/notifications.test.tsx` (fake network: every method incl. the SSE reconnect/backoff behaviour with a scripted fake `fetch`, and hooks incl. cache invalidation). No `*-integration.test.ts` for this slice (fake-network-only coverage, like B11's assets).

## AI completion and credits (B17)

- **Methods** (`network/screenwriter-client.ts`, right after the B7 AI methods): `getAiConsent`/`acceptAiConsent({version})` (version must equal the server's current `AI_CONSENT_VERSION`, read from `getAiConsent()`, else `ApiError` `VALIDATION`), `estimateAiJob(did, body)` (the live credit estimate before confirming, same pricing function the eventual charge uses), `listMyAiActivity(query?)`, `listWorkspaceAiActivity(wid, query?)`, `listAiReports(did, query?)`, `getAiReport(did, jobId)`, `convertAiNote(did, jobId, noteId)` (`noteId` is `"strengths:<i>" | "weaknesses:<i>" | "sceneNotes:<i>"` — a report's position, since it has no independently stable note ids), `decideSuggestions(ssid, body)` (combined accept-and-reject, `dryRun`, `"allPending"`; accept stays atomic — one stale suggestion comes back in `skippedStale`, not a thrown error). Adapting it would add a translation layer for no benefit today; the methods above call the real routes directly, in this file's own idiom, like every other resource. `consumables_client` stays available for a real purchase UI (mobile, RevenueCat) if one is built later — it is not deleted or discouraged, just not wired in here.
- **Hooks** (`use-ai.ts`, alongside the B7 hooks; new `use-credits.ts`): `useAiConsent()`, `useAcceptAiConsent()`, `useAiEstimate(did)` (a mutation, not cached — it depends on the live balance), `useMyAiActivity(query?)`, `useWorkspaceAiActivity(wid, query?)`, `useAiReports(did, query?)`, `useAiReport(did, jobId)` (`staleTime: Infinity`: a saved report is immutable once the job succeeds), `useConvertAiNote(did)`, `useDecideSuggestions(did, ssid)` (same invalidation as `useAcceptSuggestions`/`useRejectSuggestions`); `useCreditsBalance()` (`staleTime: 0`: a purchase or an AI job's charge/refund changes it), `useCreditPurchases(query?)`, `useCreditUsages(query?)`, `useCreditProducts()`, `useCreatePurchaseHandoff()` (invalidates the balance on success, for whenever the web purchase and its RevenueCat webhook land).
